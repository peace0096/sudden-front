# 작업 이력과 결정 사항

## 작업 이력

### 1. 기본 게임
- Rust(bevy_ecs + axum) 서버, TypeScript(three.js) 클라이언트, Protobuf3 프로토콜로 5대5 TDM 구현
- 로비·방 생성·팀 변경·방장 시작, 봇 채우기, 나간 사람 자리 봇 대체
- 클라이언트 이동 예측·보정, 서버 lag compensation
- 맵 보급창고, 소총·권총·나이프, 절차 생성 모델·텍스처·사운드
- 탄창이 비면 자동 장전

### 2. 콘텐츠 확장
- 맵 웨어하우스(실내 컨테이너 창고) 추가
- 저격소총(스코프, 볼트), 기관총, 기관단총 추가
- B키 주무기 선택 메뉴

### 3. 조작감 개선
- 벽에 비비며 이동할 때 걸리는 문제 수정 (축별 미끄러짐)
- 1/2/3 무기 슬롯
- 벽 뒤에 있는 적의 이름표 숨김
- 머리 히트박스 축소
- Ctrl/C 앉기 (누르는 동안)
- 반동·블룸 수정: 서버가 한 틱의 첫 사격 명령 조준각을 쓰도록 변경(첫 발이 위로 튀던 문제)

### 4. 게임 모드
- 일반모드 / 증강모드 분리, 증강모드 HP 150, 증강 카드 선택
- 방장이 목표 킬 수 선택 (10/20/30/50)

### 5. 증강 개편 1차
- 권총 업그레이드: 대미지 상승, 탄약 12/120
- 샷건: 주무기 → 보조무기, 대미지 상승
- 빙의: 골드, 처치 시 HP 150 초기화(감소하지 않음)
- 방패병: 주무기·나이프 사용 가능, 권총을 들 때만 방패
- 영혼 흡수: 50 회복
- 등급 확률 실버 40 / 골드 35 / 프리즘 25
- 신규: 매그넘 리볼버, 대두 바이러스, 방탄조끼, 우지 아킴보
- 연사 시 에임이 튀지 않던 문제 수정 (반동 상한 근처에서 흔들리도록)

### 6. 증강 개편 2차
- 증강모드 무기 대미지: 저격소총·기관단총 상향, 매그넘 탄퍼짐 제거·위로만 반동·대미지 상향
- 무반동: 탄퍼짐도 제거. 권총 업그레이드: 위로 튀는 반동 제거
- 신규: 더블 타임
- 대기 5초와 선택 15초 분리, 카드별 교체 버튼
- 공용: 탄퍼짐 -25%, 이동속도 -10%

### 7. 증강 개편 3차
- 매그넘 프리즘 → 골드, 우지 아킴보 골드 → 프리즘
- 방패병: 수리 제거, 방패 HP 1200
- RPG 증강 제거 → 미사일 런처(프리즘)로 대체: 연속 발사 투사체, 넓은 히트 범위, 9/36
- 신규: 테이저건(실버): 대미지 0, 5초 마비, 전기 이펙트, 1/6

### 8. 저장소
- GitHub private 저장소 https://github.com/peace0096/sudden-front 에 업로드
- GitHub CLI 설치 및 인증
- 이 문서(`docs/`) 작성

### 9. 대기실·무기·사운드 개선
- 대기실 칸별 봇 설정: 자리를 팀별 5칸 위치 고정으로 바꾸고, 방장이 빈칸마다 봇을 넣고 뺌(`SetBotSlot`). 봇 칸만 남은 팀에 사람이 들어오면 봇이 양보. 방 생성 체크박스는 초기값(방장 외 모든 칸 봇). `RoomInfo.fill_bots`는 `bot_count`로 대체
- 경기 중 나간 사람 자리를 봇으로 채우지 않고 비워 둠. 한 팀에 아무도 남지 않으면 남은 팀 기권승
- 팀 변경으로 봇 칸에 들어가면 그 봇이 옮긴 사람의 원래 칸으로 가서 인원 유지. 입장 시 양 팀 사람 수가 같으면 빈칸 있는 팀 우선
- 로비 방 목록은 목록 패널만 갱신해 방 만들기 폼의 입력·포커스 유지
- 서버 기본 포트 8080 → 8800. `PORT`가 없을 때 포트가 사용 중이면 빈 포트를 찾아 열고, 지정한 `PORT`가 사용 중이면 한 줄 오류로 종료. Vite 프록시와 e2e 기본 주소도 `PORT`를 따름
- 대기실 무기 선택 제거: 주무기는 게임 중 B키로만 고르고 다음 경기에도 유지. 쓰지 않게 된 `RoomPlayer.weapon`, `Welcome.weapons`는 `reserved`
- 총기 이름 변경: 소총 M416, 저격소총 AWP, 기관총 M249, 기관단총 UZI(아킴보 UZI Akimbo)
- 총기별 발사음: 파열음·저음·기계음·잔향을 무기마다 따로 합성해 `OfflineAudioContext`로 미리 렌더링. 샷건 펌프 소리 분리, 마스터 리미터 추가
- 에이전트 작업 지침 `AGENTS.md` 추가(`CLAUDE.md`가 가져옴)

### 10. 그래픽 개선: 스타일라이즈드 glTF 에셋 도입 (0~7단계)
- "모든 에셋 절차 생성" 원칙을 "출처·라이선스를 기록한 에셋 파일 사용"으로 변경. 캐릭터·총기(1·3인칭)·맵·이펙트를 스타일라이즈드 glTF/WebP로 단계적으로 교체하기로 함. 기준은 저사양에서도 부드럽게. 사운드는 계속 합성
- 에셋 기반 `client/src/game/art/`: manifest(단일 원본), 로더(GLB·WebP, 매직 바이트 확인, meshopt, 실패는 `[art]` 경고), Lambert 변환, 대체 모형, 히트박스 사본(`hitbox.ts`), `?art` 미리보기
- `client/public/art/LICENSES.json`과 빌드 검사 `client/scripts/check-art.mjs`(등록·라이선스·예산)
- 서버가 `/art` 아래 없는 파일에 404 응답
- 성능 측정: `Game.perf()`, `?debug&perf` 오버레이, `e2e/perf.mjs`. 그래픽 개선 전 기준선은 docs/development.md에 기록
- 에셋 선정(1단계):
  - CC0 후보 87종을 받아 측정하고, 히트박스를 겹친 비교 갤러리로 사용자가 골랐습니다.
  - 캐릭터는 Quaternius SWAT(삼각형 4.8천 개로 감량, 팀 색만 바꿔 양 팀 공용)입니다.
  - 총기는 Quaternius Ultimate Guns 위주입니다. M249와 테이저는 스크립트로 조립했고, 미사일 런처·나이프는 Toon Shooter 것입니다.
  - 맵은 Toon Shooter 컨테이너(4색)·상자·드럼통·가로등이고, 이펙트는 Kenney Particle·Splat Pack입니다.
- 변환 파이프라인(2단계): `tools/art/`(sources·fetch·inspect·build-art·recipes)로 런타임 에셋 20개(약 1.06MB)를 결정적으로 만듭니다. 출처·라이선스는 `LICENSES.json`과 자동 생성되는 `docs/credits.md`에 기록합니다.
- 캐릭터(3단계):
  - 원격 플레이어를 glTF SWAT로 바꿨습니다.
  - 이동 클립 블렌드와, `rig.ts`의 절차적 레이어(상체 정면 유지, 자세별 뼈 오프셋과 왼손 IK, 조준 pitch 분배, 앉기 다리 IK, 머리 크기)를 씁니다.
  - 원격 발사 킥과 미사일 탄체 모델을 추가했습니다.
  - `?debug&hitbox` 오버레이와 `?art` 캐릭터 벤치가 히트박스 일치를 자동 검사합니다.
  - 캐릭터당 그리기 호출은 약 15회에서 4회로 줄었습니다.
- 1인칭(4단계):
  - 박스 손·총을 SWAT 팔과 glTF 총으로 바꿨습니다.
  - 총은 기존 화면 위치에 두고, 손은 IK로 손잡이·지지점에 맞춥니다.
  - 반동·재장전·볼트/펌프·칼질·흔들림 곡선은 그대로입니다. 재장전 때는 왼손이 내려갔다 돌아오고, 샷건 펌프 때는 왼손이 앞뒤로 움직입니다.
  - 팀 색 소매를 입혔고, 1인칭 그리기 호출은 약 12회에서 2~3회로 줄었습니다.
- 맵(5단계):
  - 컨테이너(4색·기울어진 것)·상자·드럼통·가로등을 키트 모델 `InstancedMesh`로 바꿔 충돌 박스에 1cm 이내로 맞췄습니다.
  - 트러스·바닥선은 각각 한 메시로, 셔터·광고판·창·환기창·천장 조명은 종류별 인스턴스로 합쳤습니다.
  - 정적 맵 그리기 호출은 74/91회에서 16/12회로 줄었습니다.
  - `?debug&collision` 오버레이와 `?art` 맵 벤치를 추가했습니다.
- 이펙트(6단계):
  - 효과마다 새 스프라이트를 만들던 방식을 Kenney 아틀라스 기반 인스턴스 파티클 배치로 바꿨습니다.
  - 예광탄은 1px 선에서 리본으로 바꿨습니다.
  - 박스 면에 붙는 데칼 풀(탄흔·핏자국·그을음)을 추가했습니다.
  - 폭발은 섬광·불덩이·충격파·불꽃·연기·그을음으로 구성합니다.
  - 1인칭 총구 화염도 아틀라스를 씁니다.
  - 이펙트 그리기 호출은 최대 4회이고, 발사할 때마다 새로 할당하지 않습니다.
- 정리와 최종 리뷰 반영(7단계):
  - 쓰지 않는 코드를 지우고, 이펙트 예산을 manifest로 모았습니다. 그림자 맵 경고(PCFSoft)를 없앴습니다.
  - 시야 밖 캐릭터는 애니메이션 계산을 건너뜁니다. 몇 명만 보이는 장면에서 캐릭터 갱신 비용이 0.33ms에서 0.10ms로 줄었습니다.
  - 경기가 끝나면 맵 GPU 자원을 해제하고 WebGL 컨텍스트를 놓습니다.
  - 실패한 에셋은 다음 경기 때 다시 받습니다.
  - `check-art`가 파일 내용까지 잠그고, `build-art`가 고정 해시와 다른 원본을 거부합니다. 에셋 도구의 경로 값을 검증합니다.
- 성능 결과(전체, SwiftShader):
  - 경기 전체 그리기 호출은 약 190~200회에서 40회 안팎으로 줄었습니다.
  - 삼각형은 약 4천 개에서 9만 개로 늘었습니다(스타일라이즈드 모델).
  - 셰이더 프로그램은 17~23개, 에셋 다운로드는 약 1.06MB입니다.

  - 점수 막대는 ME / 목표 / RIVAL이고, Tab 점수판은 순위 한 목록입니다. VICTORY는 승자만 봅니다.

  - `Rig.wristBend()` 측정과 `art.mjs`의 나이프 손목 20° 이하 검사를 추가했습니다. 다른 무기 값은 INFO로 출력합니다.

### 12. 소총·기관단총 반동·탄퍼짐 완화
- 반동(클라이언트 `RECOIL_PER_SHOT`, 위/옆 rad): 소총 0.012/0.005 → 0.0075/0.003, 기관단총 0.008/0.005 → 0.005/0.003 (약 −40%)
- 탄퍼짐(서버 `weapons.rs` 표 값, `SPREAD_SCALE` 적용 전): 소총 정지 0.002→0.0016, 이동 0.014→0.009, 발당 블룸 0.0035→0.0022, 블룸 최대 0.03→0.018 / 기관단총 정지 0.0015→0.0013, 이동 0.009→0.006, 발당 블룸 0.0025→0.0016, 블룸 최대 0.022→0.013
- 기관단총 정지 탄퍼짐은 권총(0.0012)보다 조금 높게 남겼습니다(권총이 정지 정확도가 더 높다는 규칙). 우지 아킴보는 기관단총 탄퍼짐을 물려받아 함께 줄었고, 반동은 그대로입니다.
- 봇도 같은 탄퍼짐을 쓰므로 소총·기관단총 봇의 명중률도 올라갑니다.
- 값에 묶인 검사를 맞췄습니다: `bloom_recovers_once_the_trigger_is_released`는 소총 `bloom_max` 기준으로, `e2e/recoil.mjs`의 점프·크로스헤어·흩어짐 기준은 새 크기에 맞춰 낮췄습니다. 사용자가 직접 확인하기로 해서 테스트는 이 작업에서 돌리지 않았습니다.

### 13. 대두 바이러스 상향, 준비(레디), Tab 조작키 안내
- 대두 바이러스: 처치에 기여할 때마다 머리 크기 +10% → +25%(`BIG_HEAD_STEP` 0.25), 대신 최대 3배(`BIG_HEAD_MAX`)에서 멈춥니다. 캐릭터의 화면 밖 판정 경계도 머리 2배 → 3배 기준으로 넓혔습니다(`hitbox.ts`의 `HEAD_SCALE_MAX`).
- 준비: 방장을 뺀 모든 플레이어가 준비해야 방장이 시작할 수 있습니다. 프로토콜 `SetReady`(ClientMessage 14), `RoomPlayer.ready`(7). 대기실에 준비/준비 취소 버튼과 READY 표시가 생겼고, 방장의 시작 버튼은 모두 준비할 때까지 꺼집니다. 준비는 경기가 시작되면 풀립니다.
- Tab: 점수판 아래에 조작키 목록을, 증강모드에서는 보유 증강(고른 카드와 더블 타임으로 얻은 증강)의 등급·설명을 함께 보여 줍니다. 결과 화면에는 나오지 않습니다.
- 사용자가 직접 확인하기로 해서 이 작업에서는 테스트를 돌리지 않았습니다. 손님이 있는 hub 테스트 4개와 e2e 6개(play·kill-target·recoil·wall-rub·crouch-keys·ffa)에는 시작 전 준비 단계를 넣었습니다.

### 14. 도중 참가, 점프, 마우스 휠 무기 교체, 발소리
- 도중 참가: 경기 중인 방에 빈 칸이 있으면 방 목록의 "도중 참가"로 들어갑니다. 봇 칸은 경기 중에 양보하지 않고, 팀은 인원이 적은 쪽으로, 개인전은 번호가 가장 낮은 빈칸으로 갑니다. 재투입처럼 적에게서 먼 곳에 3초 보호로 나타나고, 증강모드면 카드 선택 중엔 패를 받고 그 뒤엔 바로 무작위 증강을 받습니다. 결과 화면 중에는 거절합니다.
- 점프: Space(누르고 있으면 착지 즉시 다시). 이륙 7.5m/s·중력 20m/s²로 발이 약 1.34m 오릅니다. 이동·충돌이 발 높이를 다루게 바꿔 낮은 상자·드럼통 위에 올라서고, 상자를 밟고 2단 상자·컨테이너까지 오를 수 있습니다. 프로토콜 `InputCmd.jump`(14), `PlayerState.y`(21)·`vy`(22), `GameConfig.jump_speed`(16)·`gravity`(17). 히트박스·lag compensation 기록·총구·미사일·봇 시야가 높이를 따라가고, 공중에서 죽은 몸은 떨어집니다. 원격 캐릭터에 점프 동작 클립은 없어 몸만 떴다 내려옵니다.
- 마우스 휠: 아래로 다음 칸, 위로 이전 칸(1→2→3→1). 트랙패드 입력은 모아서 한 칸씩, 0.12초 간격.
- 발소리: 거의 들리지 않던 내 발소리를 새로 합성하고(낮은 쿵 + 짧은 자갈 소리, 발마다 조금씩 다름), 다른 플레이어 발소리를 거리·좌우에 따라 30m까지 들려줍니다. 앉아 걷기와 공중에서는 소리가 없고, 착지하면 쿵 소리가 납니다.
- 사용자가 직접 확인하기로 해서 테스트는 돌리지 않고 컴파일만 확인했습니다. 점프 물리 테스트 6개와 도중 참가 hub 테스트 8개를 추가했습니다.

### 15. 수류탄, 대기실 모드·맵 변경, 맵 엄폐물·컨테이너 계단, 처치 배너, 기울어진 컨테이너 충돌
- 수류탄(4번 칸, `WeaponKind.GRENADE`): 목숨당 1개, 던진 지 3초(90틱) 뒤 놓인 자리에서 폭발(중심 110, 반경 5m, 미사일과 같은 감쇠·엄폐·방패 규칙). 중력 12m/s²로 날아가며 벽·바닥·천장·맵 가장자리에 튕기고 굴러가다 멈춥니다. 던지면 그 전 칸 무기로 돌아오고, 봇도 사람과 같은 입력으로 가끔 던집니다. 프로토콜 `Snapshot.grenades`(20)·`grenades_left`(21), `GameEvent.grenade_thrown`(7, `ThrowEvent`). 모델은 스크립트로 만든 `weapons/grenade.glb`(procedural, CC0)를 손에 든 것과 날아가는 것에 함께 씁니다.
- 대기실에서 방장이 게임 모드와 맵을 바꿀 수 있습니다(`SetGameMode` 15, `SetMap` 16). 목표 킬 수와 같은 줄의 선택 상자이고, 방 목록과 손님 화면에 바로 반영됩니다.
- 보급창고: 스폰~중앙 가운데 통로, 남/북 통로 가운데, 실내 창고 끝과 중앙 사이, 스폰 옆에 엄폐물(상자 더미, 높이 1.1m 콘크리트 방벽, 드럼통, 컨테이너)을 반쪽마다 13개 더했습니다.
- 웨어하우스: 단층 컨테이너마다(반쪽에 6개) 상자 1개 → 2단 상자 계단을 붙여 바닥에서 올라갈 수 있게 했습니다(점프 1.34m로 1.2 → 2.4 → 2.6m).
- 처치 배너: 내 처치마다 화면 위 가운데에 KILL, 4초 안에 이어지면 DOUBLE KILL → TRIPLE KILL → QUADRA KILL → PENTA KILL…, 첫 처치가 헤드샷이면 HEADSHOT을 띄웁니다. 처치 수만큼의 탄환과 구멍 난 해골 그림은 상용 게임 그림을 옮기지 않고 코드(SVG)로 새로 그렸고, 연속 처치 효과음을 합성했습니다. 배너 아래에 처치한 적의 닉네임을 팀 색으로 보여 줍니다.
- 기울어진 컨테이너: 충돌이 4.2m 높이 직육면체 하나라 낮은 쪽 위 빈 공간에서 총알이 막히던 문제를 고쳤습니다. 서버가 기울기(`MapProp.tilt`, 0.34rad)를 정해 보내고, 충돌은 그 기울기를 따라 자른 0.5m 조각 상자 14개입니다(경사면과의 차이 최대 약 0.18m). 조각 윗면에도 설 수 있어, 옆 컨테이너 위에서 건너가 경사를 따라 올라갈 수 있습니다.

### 16. 왕대두모드
- 세 번째 모드 `GameMode.BIG_HEAD`(왕대두모드). 처치 +1레벨·사망 −1레벨(−5~3), 마이너스에서 처치하면 바로 1레벨, 레벨별 머리 배율(0.4~2.6)을 모델과 머리 히트박스에 적용합니다. 3레벨이 되면 20초 동안 무적·HP 회복·뿅망치만 사용·이동속도 5.94m/s인 "무적의 왕대두"가 되고, 끝나면 0레벨과 새 무기로 돌아갑니다. 도트 샷(가장 작은 머리를 헤드샷으로 처치)·큐트 샷(뿅망치로 처치)을 서버가 판정해 알립니다. 자세한 규칙은 [big-head-mode.md](big-head-mode.md).
- 프로토콜: `WeaponKind.HAMMER`(14), `GameMode.BIG_HEAD`(3), `SpecialKill` 열거형과 `KillEvent.special`(5), `GameConfig.min_level`·`max_level`·`king_time`(18~20), `PlayerState.level`·`king_left`(23·24), `ScoreEntry.level`(7).
- 서버: `big_head.rs`(상수와 `crown`), `fire_weapons`의 무적·레벨·특수 샷, 새 시스템 `update_kings`(왕대두 시간), `respawn_players`의 부활 때 즉위, `Weapon::take_hammer`와 뿅망치일 때 `switch_to` 거부, 봇의 왕대두 추적·휘두르기. 테스트 12개(게임)·1개(허브).
- 클라이언트: 대기실·방 만들기 모드 선택, 레벨 패널, 즉위·종료 알림과 팡파르, 금관 스프라이트, 뿅망치 모델(procedural)·내려치기·'뿅' 소리, 도트 샷·큐트 샷 배너와 킬 피드, 점수판 레벨 열, Tab 규칙 요약.
- 사용자가 준 규칙 설명에 없던 부분은 이렇게 정했습니다: 시작 레벨 0, 왕대두가 끝나면 0레벨, 레벨은 부활해도 유지, 왕대두는 총알을 막되 피해는 없음, 뿅망치는 한 방(200), 도트 샷의 "가장 작은 머리"는 경기 안 최저 레벨(동률 포함)이면서 마이너스 레벨, 둘 다 해당하면 큐트 샷, HP·무기 선택·수류탄·목표 킬은 일반모드와 같음.

### 17. 뿅망치를 치켜든 3인칭 자세
- 3인칭 뿅망치가 나이프 자세(팔을 낮춰 앞으로 든 자세)를 쓰던 것을, 망치를 얼굴 옆까지 치켜든 자세(`holds.hammer`)로 바꿨습니다. 주먹 1.64m, 망치 머리 1.85m, 몸 앞 0.34m입니다.
- 오프셋은 게임의 `Rig.closeFist`(2관절 IK)로 구했습니다. 주먹 자리와 망치 방향을 격자로 바꿔 가며 손목 꺾임이 작고 망치 머리가 주먹 위·바깥쪽·몸 앞 0.33m 이상인 조합을 고른 뒤, 클립 자세에 대한 뼈 회전으로 바꿨습니다. 팔이 짧아(어깨~손목 0.4m) 더 높이는 들 수 없습니다.
- 왕대두 머리가 아주 크면(5배) 목도리와 헬멧이 어깨를 덮어, 3/4 앞 시점에서는 망치 일부가 가려집니다.

| 개인전은 새 중립(회색) 군복, 이름표는 적 빨강 | 빨강·파랑을 쓰면 팀이 있는 것처럼 보임. 개인전에서는 모두가 적 |

## 알려진 이슈와 미검증 항목

- **밸런스 미검증**: 증강·무기 수치는 실제 대전으로 검증하지 않았습니다.
- **왕대두모드**: 레벨별 머리 배율, 20초, 뿅망치 한 방·사거리·이동속도는 사람이 하는 대전으로 검증하지 않았습니다. 봇만의 테스트에서는 팀전 30킬 중 19킬이 큐트 샷이었습니다(봇은 왕대두를 피하지 않음). 왕대두가 된 순간 서버는 뿅망치 속도로 움직이지만 클라이언트는 그 스냅샷을 받을 때까지 이전 무기 속도로 예측해, 즉위·종료 직후 위치가 조금 보정될 수 있습니다(부활 때와 같은 종류).
- **Ctrl+W**: 앉기 중 W를 누르면 브라우저 탭 닫기 단축키와 겹칠 수 있습니다. 포인터 잠금 상태의 실제 동작은 사람이 확인하지 않았습니다. C 키 앉기를 대안으로 둡니다.
- **미사일·테이저의 브라우저 실사격**: 서버 단위 테스트와 화면 스크린샷으로만 확인했고, 브라우저에서 실제로 발사해 맞히는 e2e는 없습니다. 수류탄도 브라우저 e2e(`grenade.mjs`)는 던지기·폭발 시점까지만 보고, 피해는 서버 단위 테스트로 확인합니다.
- **수류탄의 한계**: 경고 표시(근처 수류탄 아이콘)가 없고, 봇은 수류탄을 피하지 않습니다. 날아가는 수류탄은 스냅샷 사이를 최대 0.1초 직선으로 외삽해서, 벽에 튕기는 순간 한두 프레임 벽에 살짝 들어가 보일 수 있습니다.
- **기울어진 컨테이너**: 충돌 조각이 계단 모양이라 경사면 위에 선 캐릭터가 최대 약 0.18m 떠 보이거나 묻혀 보일 수 있고, 경사를 오를 때 조각마다 점프해야 합니다.
- **미사일 lag compensation 없음**: 빠르게 움직이는 표적은 클라이언트 화면과 폭발 위치가 어긋날 수 있습니다.
- **play.mjs 간헐 실패**:
  - 정지 상태 예측 오차가 0.13m로 한 번, 개인전 작업 중(다른 e2e를 연달아 돌린 직후) 0.078m로 한 번 실패했습니다. 둘 다 재실행하면 0.0000m로 통과했고, 원인은 미확인입니다.
  - 별도로, 권총 확인 직후 3번(나이프)을 누르기 전에 호스트가 봇에게 죽으면 나이프 전환 대기가 30초를 넘겨 실패합니다. 죽은 동안 눌린 무기 칸 키는 버려지기 때문입니다(`game.ts`). 재실행하면 통과합니다.
- **README 무기 표**: 루트 README의 이동속도·탄퍼짐은 공용 계수 적용 전 값입니다(실제는 이동속도 ×0.9, 탄퍼짐 ×0.75).
- **총기 사운드 실전 청취 미검증**: 게임과 같은 경로로 렌더링한 WAV를 사람이 들어 확인했지만, 실제 경기(여러 총기 동시 발사, 거리별 소리)에서는 확인하지 않았습니다. 실내(웨어하우스)와 실외(보급창고) 맵이 같은 잔향을 씁니다.
- **full-match.mjs 무기 교체**: 헤드리스 렌더러는 첫 화면까지 7~13초가 걸려 재투입 보호(3초) 중 즉시 교체를 확인할 수 없습니다. 첫 경기에서는 서버가 선택을 받았는지만 보고, 실제 지급은 다음 경기에서 확인합니다.
- **실제 GPU 성능 미측정**: 성능 기준선은 SwiftShader(소프트웨어 렌더링)로만 쟀습니다. 내장 그래픽 노트북 실측은 그래픽 개선 마지막 단계에서 `?debug&perf`로 사람이 해야 합니다.
- **캐릭터 모델의 한계**:
  - 팔이 짧아(어깨~손목 0.4m) 3인칭 긴 총의 앞손이 핸드가드까지 닿지 못하고 탄창 우물·리시버 앞을 쥡니다. 소총 자세는 몸을 약 40° 비틉니다.
  - 앉으면 무릎이 다리 히트박스 밖으로 0.1~0.2m 나옵니다(보이는 것만).
  - 빠른 이동(애니메이션 배속 상한 1.4 초과)에서 발이 약간 미끄러집니다.
  - 서서 아래로 끝까지(−1.45) 조준하면 목이 1.448m로 조금 내려갑니다.
  - 투과 화면에서는 모델 안쪽의 가려진 부분도 빨갛게 보입니다(박스 캐릭터 때와 같음).
- **1인칭의 한계**:
  - 총을 쥔 오른손목은 약 64°(아킴보 71°) 꺾여 있습니다(`art.mjs`가 INFO로 출력). 아래팔이 무기와 무관하게 오른쪽 아래에서 47° 올라오는데 총을 쥔 손은 총열을 따라 수평이기 때문입니다. 고치려면 전 무기의 1인칭 팔 배치를 바꿔야 해서 나이프만 고쳤습니다. 3인칭 총 자세의 오른손목은 16~30°(런처 16°, 소총류 22°, 권총류 30°)입니다.
  - 왼손목도 꺾여 있습니다. 1인칭 받침손은 25°(재장전 중 52°), 아킴보 왼손은 94.5°이고, 3인칭 받침손은 긴 총 66~75°, 권총류 46°입니다(`art.mjs` INFO).
  - 총이 단일 메시라 권총 재장전은 탄창이 빠지는 대신 숙임·기울임으로만 보이고, 저격총 볼트 동작에 손이 가지 않습니다.
  - 미사일 런처가 화면 오른쪽 아래를 이전보다 많이 가립니다.
  - 웨어하우스(실내)도 야외에 맞춘 1인칭 조명을 씁니다.
- **맵 키트**:
  - 컨테이너의 번호 글자·얼룩 텍스처는 스타일라이즈드 단색 모델로 바뀌면서 없어졌습니다.
  - `InstancedMesh`는 하나라도 보이면 전부 그려서 정적 맵 삼각형이 약 3만 개로 늘었습니다.
  - 키트 파일을 못 불러오면 그 종류는 단색 박스로 그립니다. 이때 가로등이 예전 4메시 모델로 돌아가면 보급창고 정적 그리기 호출이 예산(35)을 넘습니다.
- **이펙트**:
  - 가산 합성 이펙트는 밝은 하늘 앞에서 거의 흰색으로 보입니다.
  - 땅에 맞은 총알은 먼지만 남고 탄흔은 없습니다(서버 판정 광선에 땅이 없음).
  - 아틀라스의 `arc`·`tracer` 칸은 쓰지 않습니다(테이저 전류는 코드, 예광탄은 셰이더 발광).
  - 테이저에 맞은 캐릭터의 전류 효과는 메시 10개라, 맞은 동안 그 캐릭터의 그리기 호출이 4회에서 13회로 늘어납니다.
