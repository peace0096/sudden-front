# Sudden Front

웹 브라우저에서 즐기는 1인칭 FPS. 5대5 팀 데스매치와 최대 10명 개인전을 지원합니다. 서버는 Rust + Bevy ECS, 클라이언트는 TypeScript + three.js, 통신은 WebSocket 위의 Protobuf3입니다.

## 실행

```powershell
cd client; npm install; npm run build
cd ..\server; cargo run --release
```

macOS·Linux에서는 프로젝트 폴더의 `./run.sh` 하나로 클라이언트 빌드(패키지가 없거나 `package-lock.json`이 바뀌었을 때만 `npm ci`) → 서버 빌드(`cargo build --release`) → 서버 시작까지 합니다. `PORT=8810 ./run.sh`처럼 포트를 줄 수 있고, 그 포트를 이미 다른 프로세스가 쓰고 있으면 알려 주며, 같은 네트워크에서 접속할 주소(`http://<IP>:<포트>`)도 출력합니다.

브라우저에서 http://localhost:8800 을 엽니다. 같은 네트워크의 다른 PC는 `http://<서버 IP>:8800` 으로 접속합니다. 8800이 사용 중이면 8801부터 빈 포트를 찾아 열고 실제 주소를 출력합니다. `PORT` 환경 변수로 포트를 직접 정할 수 있으며, 그 포트가 사용 중이면 서버는 이유를 알리고 종료합니다.

클라이언트 개발 시에는 서버를 켠 채 `cd client; npm run dev` 후 http://localhost:5173 을 사용합니다. 서버가 8800이 아닌 포트로 열렸다면 `npm run dev`에도 같은 `PORT` 환경 변수를 줍니다.

| 입력 | 동작 |
| --- | --- |
| W A S D | 이동 |
| 마우스 | 조준. 감도는 Esc 화면이나 로비(방 목록)에서 조절하며 브라우저에 저장됩니다. 스코프를 켜면 시야각 비율만큼 자동으로 낮아집니다 |

| 4 | 수류탄 (목숨당 1개, 왼쪽 클릭으로 던지면 3초 뒤 폭발하고 들고 있던 무기로 돌아옴) |
| 마우스 휠 | 무기 바꾸기 (아래로 다음, 위로 이전 칸. 수류탄이 남아 있으면 4번 칸 포함) |

## 게임 규칙

- 팀 데스매치: 방장이 대기실에서 고른 목표 킬 수(10/20/30/50, 기본 30)를 먼저 달성한 팀이 승리합니다. 팀당 5명, 방 최대 10명입니다.
- 개인전: 팀 없이 최대 10명이 싸우고, 목표 킬 수(10/20/30/50, 기본 20)를 먼저 채운 사람이 승리합니다. 모두 회색 중립 군복을 입고, 나를 뺀 모두가 적입니다.
- 사망 3초 후 탄약이 가득 찬 상태로 재투입되며 3초간 보호됩니다. 먼저 발사하면 보호가 풀립니다.
- 아군 사격과 자기 피해는 없습니다(수류탄·미사일 폭발 포함).
- 적을 처치하면 화면 위에 KILL이 뜨고, 4초 안에 이어서 처치하면 DOUBLE KILL·TRIPLE KILL·QUADRA KILL·PENTA KILL…로 강조됩니다. 첫 처치가 헤드샷이면 HEADSHOT(구멍 난 해골)이 뜹니다. 배너 아래에는 처치한 적의 닉네임이 나옵니다.
- 맵: 보급창고(야외, 통로마다 엄폐물), 웨어하우스(실내 컨테이너 창고, 상자 계단으로 단층 컨테이너 위에 올라감). 방을 만들 때 고르고, 모드(일반/증강/왕대두)와 함께 대기실에서 방장이 바꿀 수 있습니다.
- 주무기는 게임 중 B키로 고릅니다. 재투입 보호 중에는 즉시, 그 외에는 다음 재투입 때 적용되며, 고른 무기는 다음 경기에도 유지됩니다.

| 총기 | 탄약 | 머리/몸통/다리 | RPM | 이동속도 | 장전 | 정지 시 탄퍼짐 (rad) |
| --- | --- | --- | --- | --- | --- | --- |
| 소총 M416 | 30/120 | 100/34/25 | 600 | 5.2 | 2.2초 | 0.0016 |
| 저격소총 AWP | 5/20 | 200/100/70 | 볼트 1.3초 | 4.7 | 3.0초 | 0.009, 스코프 0.0002 |
| 기관총 M249 | 100/200 | 100/40/30 | 1000 | 3.7 | 4.5초 | 0.018 |
| 기관단총 UZI | 25/125 | 72/24/18 | 800 | 6.3 | 1.8초 | 0.0013 |
| 권총 PT-9 (공통) | 12/36 | 70/22/16 | 240 | 5.6 | 1.5초 | 0.0012 |
| 나이프 (공통) | - | 100/60/45 | 휘두르기 0.55초 | 6.0 | - | 사거리 2.2m |
| 수류탄 HG-3 (공통) | 목숨당 1개 | 폭발 중심 110 (반경 5m) | 던진 뒤 0.6초 | 5.6 | - | 던진 지 3초 뒤 폭발 |

무기를 바꾸면 0.35초의 꺼내는 시간이 있고, 진행 중인 장전은 취소됩니다. 탄약은 무기별로 유지됩니다.

수치는 `server/src/game/weapons.rs` 한 곳에서 바꿀 수 있습니다.
- 방을 만들면 로비의 모든 사용자에게 목록으로 보이고, 방장이 시작을 누르면 시작합니다.
- 대기실은 팀마다 5칸이고, 방장이 빈칸마다 봇을 넣거나 뺄 수 있습니다. 방을 만들 때 "빈 자리는 봇으로 채우기"를 켜면 방장 자리를 뺀 모든 칸이 봇으로 시작합니다. 봇 칸만 남은 팀에 사람이 들어오면 봇이 자리를 비켜 주고, 팀을 바꿔 들어온 경우에는 그 봇이 옮긴 사람의 원래 칸으로 갑니다. 양 팀에 사람이나 봇이 최소 1명씩 있어야 시작할 수 있습니다.
- 방장을 뺀 모든 플레이어가 대기실에서 "준비"를 눌러야 방장이 시작할 수 있습니다(봇은 늘 준비된 것으로 봄). 준비는 경기가 시작되면 풀려서, 다음 경기 전에 다시 누릅니다.
- 게임 중에 나간 사람의 자리는 비워 둡니다. 한 팀에 사람도 봇도 남지 않으면 남은 팀이 기권승합니다.
- 경기 중에도 빈 자리가 있으면 방 목록의 "도중 참가"로 들어갈 수 있습니다(봇 칸은 경기 중에 양보하지 않음).

## 구조

```
proto/game.proto          패킷 정의의 단일 원본 (Rust, TS 코드 생성)
server/AGENTS.md          서버 코드 규칙 (도메인별 패키지, 순수 함수와 단위 테스트, fmt·clippy)
server/src/net.rs         WebSocket <-> 허브 스레드
server/src/hub/           로비, 방, 30Hz 틱 루프
server/src/game/          방마다 하나의 Bevy ECS World
  systems/                입력 → 무기 → 사격 → 부활 순서의 규칙 시스템, 도메인마다 한 파일
  systems/bot.rs          봇 AI (사람과 같은 InputCmd 큐로 입력)
  weapons.rs              총기 스탯 표
  map.rs                  맵 데이터 (점대칭 생성, MatchStart로 클라이언트에 전송)
client/src/game/          렌더링, 예측, HUD, 사운드 (캐릭터·총기·맵 소품·이펙트는 glTF/WebP 에셋, 사운드와 벽·하늘·이름표 텍스처는 코드로 생성)
client/public/art/        glTF·WebP 에셋과 파일별 라이선스 기록(LICENSES.json)
tools/art/                에셋 파이프라인 (원본 팩 받기, 측정, 레시피로 변환)
```

서버가 모든 판정을 결정합니다. 클라이언트는 이동을 예측한 뒤 서버 상태로 보정하고(`movement.ts`는 서버의 `step_move`와 동일해야 합니다), 서버는 사격 시 클라이언트가 보던 시점으로 표적 위치를 되돌려 판정합니다(lag compensation).

## 테스트

```powershell
cd server; cargo test --release          # 게임 규칙
# 서버 실행 후 (Microsoft Edge 필요)
cd client
node e2e/play.mjs                        # 브라우저 2개로 로비~전투 흐름
node e2e/kill-target.mjs                 # 방장의 목표 킬 수·칸별 봇 설정과 실제 경기 반영
node e2e/ffa.mjs                         # 개인전: 10칸 대기실·봇 칸, 목표 킬 경기, 승자만 VICTORY, 기권승
node e2e/full-match.mjs                  # 게임 중 무기 선택, 목표 킬 종료~대기실 복귀~재시작
node e2e/art.mjs                         # ?art 미리보기에서 에셋 로드 실패·콘솔 에러 0건
node e2e/perf.mjs                        # 맵별 draw call·프레임 시간 측정 (e2e-shots/perf.json)
```

## 게임 모드

방을 만들 때 대전 방식(팀 데스매치 / 개인전)과 모드(일반 / 증강 / 왕대두)를 따로 고릅니다. 여섯 조합 모두 됩니다.

- **일반모드**: HP 100, 시작 대기 없음.
- **증강모드**: HP 150. 시작하면 15초 안에 카드 3장 중 하나를 고르며 그 판 동안 유지됩니다. 카드마다 아래의 변경 버튼으로 한 번씩 바꿀 수 있고, 이미 나온 증강은 다시 나오지 않습니다. 고르지 않으면 무작위로 정해지고 봇도 무작위로 고릅니다. 모두 고르면 곧바로 5초 대기 후 전투가 시작됩니다.

| 등급 (확률) | 증강 |
|---|---|
| 실버 (40%) | 무한 장전, 영혼 흡수, 권총 업그레이드, 빠른 준비, 방탄조끼, 테이저건 |
| 골드 (35%) | 샷건, 때로는 휴식이, 방패병, 작은 머리, 빙의, 대두 바이러스, 매그넘 리볼버, 더블 타임 |
| 프리즘 (25%) | 투과, 무반동, 빌려쓰기, 미사일 런처, 우지 아킴보 |

- **왕대두모드**: HP 100. 적을 처치하면 레벨이 오르고 머리(헤드샷 판정)가 커지며, 죽으면 레벨이 내려가고 머리가 작아집니다. 자세한 규칙은 [docs/big-head-mode.md](docs/big-head-mode.md)에 있습니다.

| 레벨 | −5 | −4 | −3 | −2 | −1 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|---|---|---|
| 머리 배율 | 0.4 | 0.5 | 0.6 | 0.7 | 0.85 | 1.0 | 1.25 | 1.55 | 2.6 (왕대두) |

- 처치 +1레벨, 사망 −1레벨. 마이너스 레벨에서 처치하면 바로 1레벨이 됩니다.
- 3레벨이 되면 **무적의 왕대두**: 20초 동안 무적이고 조금 빨라지며(5.94m/s), 뿅망치(근접 2.5m, 한 방)만 쓸 수 있습니다. 끝나면 0레벨로 돌아가고 무기를 새로 받습니다.
- **도트 샷**: 머리가 가장 작은 상대(마이너스 레벨)를 헤드샷으로 처치. **큐트 샷**: 뿅망치로 처치.
